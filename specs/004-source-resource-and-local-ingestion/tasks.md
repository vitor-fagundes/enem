### T-007: Implement streaming SHA-256 hasher in hasher.py (test-first)

**Files**: `packages/ingestion/src/enem_rei_ingestion/hasher.py`, `tests/python/test_hasher.py`
**FRs**: FR-015 (step 3), FR-016 | **Invariants**: INV-004-002
**Implementation**: **(test-first for integrity)** Write focused correctness tests in `test_hasher.py` first, then implement two functions sharing the same design — each maintains a single `hashlib.sha256()` object updated chunk by chunk:

1. `stream_copy_hash(src, dst, max_bytes=None, chunk_size=65536) -> (sha256_hex: str, byte_count: int)`:
   - Read from `src` in fixed-size chunks. For each chunk: update hash, write to `dst`, accumulate byte count.
   - If `max_bytes` is not None and accumulated bytes would exceed it, raise `SizeLimitExceeded` before writing the excess.
   - Return hex digest and total byte count after EOF.
   - Single read pass: hash and copy happen simultaneously, never in separate reads (FR-015 step 3).
   - Accept file-like objects with `.read()` and `.write()`.

2. `stream_verify_hash(src, max_bytes=None, chunk_size=65536) -> (sha256_hex: str, byte_count: int)`:
   - Read-only SHA-256 verification. Same chunked design as `stream_copy_hash` but without writing.
   - Used for payload revalidation (FR-016) without copying.

Both functions: empty input produces SHA-256 of empty bytes (`e3b0c44298fc1c149afbf4c8996fb924...`) and byte count 0.

Focused tests in `test_hasher.py`:
- `stream_copy_hash` on known content `b"hello world"` produces expected SHA-256 and byte count 11.
- `stream_verify_hash` on same content produces identical hash and byte count.
- Empty input: both functions return SHA-256 of empty bytes and byte count 0.
- Destination receives exact bytes from `stream_copy_hash`: read back and compare.
- `stream_verify_hash` does not write: no destination argument.
- Limit enforcement: 100-byte content with `max_bytes=50` raises `SizeLimitExceeded`; destination receives at most 50 bytes.
- Limit boundary: content exactly at limit succeeds; one byte over fails.
**Validation**: `uv run --frozen pytest tests/python/test_hasher.py -v` — all focused tests pass.
**Dependencies**: T-001

### T-013: Implement no-clobber publication in store.py (test-first)

**Files**: `packages/ingestion/src/enem_rei_ingestion/store.py`, `tests/python/test_store.py`
**FRs**: FR-015 (step 5), FR-016 | **Invariants**: INV-004-003, INV-004-012
**Implementation**: **(test-first for integrity and publication)** Write focused no-clobber tests in `test_store.py` first, then implement `publish_payload(resources_fd, tmp_name, sha256_hex) -> storage_locator`:
- Create SHA-256 subdirectory: `os.mkdir(sha256_hex, 0o755, dir_fd=resources_fd)`. If `FileExistsError`, the directory already exists (potential reuse scenario — caller handles).
- Open the SHA-256 directory: `os.open(sha256_hex, O_RDONLY | O_DIRECTORY | O_NOFOLLOW, dir_fd=resources_fd)` → `sha256_fd`.
- Publish: `os.link(tmp_name, "payload", src_dir_fd=resources_fd, dst_dir_fd=sha256_fd)` — atomically creates hard link; fails with `FileExistsError` if `payload` already exists. This is the no-clobber guarantee: `os.link()` never silently overwrites, unlike `os.rename()` on Linux.
- Remove temp: `os.unlink(tmp_name, dir_fd=resources_fd)`.
- Close `sha256_fd`.
- Return relative storage locator: `raw/resources/<sha256_hex>/payload`.
- If `os.link()` fails with `FileExistsError`, do not unlink temp — caller decides (reuse path).

Focused tests in `test_store.py`:
- New payload: temp published to `<sha256>/payload`; content matches.
- Existing payload: `os.link()` fails with `FileExistsError`; original content unchanged (immutability).
- Published payload is immutable: content verified after publication.

## Unresolved Implementation Decisions

3. **Default limit values**: Exact finite defaults for `max_input_bytes`, `max_zip_members`, etc. — must be finite and documented, values chosen at implementation.
